AI 에이전트 프레임워크 비교 — LangChain, CrewAI, AutoGen 어떤 걸 쓸까

2025년부터 AI 개발의 중심이 "챗봇"에서 "에이전트"로 옮겨갔다. 단순히 질문에 답하는 게 아니라, 스스로 판단하고 도구를 쓰고 작업을 완수하는 AI다. 이 에이전트를 만들기 위한 프레임워크가 쏟아지고 있는데, 대표적인 3개를 비교해 본다. ## AI 에이전트란? 에이전트는 LLM이 "도구"를 사용할 수 있게 만든 구조다. 일반 챗봇은 텍스트만 주고받지만, 에이전트는 검색, 코드 실행, API 호출, 파일 작성 등의 행동을 한다. 핵심 루프: 생각(Reason) → 행동(Act) → 관찰(Observe) → 다시 생각 이걸 ReAct 패턴이라고 부른다. 에이전트 프레임워크는 이 루프를 쉽게 구현하게 해준다. ## LangChain / LangGraph 가장 먼저 등장했고, 생태계가 가장 넓다. **장점**: 커뮤니티가 크고 자료가 많다. 스택오버플로우, 블로그, 유튜브 튜토리얼이 풍부하다. LangGraph로 복잡한 멀티스텝 워크플로우를 그래프 형태로 설계할 수 있다. LangSmith로 디버깅과 모니터링이 가능하다. Tool, Memory, Retriever 등 컴포넌트가 모듈화되어 있다. **단점**: 추상화가 너무 많아서 디버깅이 어려울 때가 있다. "마법"처럼 동작하는 부분이 있다. 버전 업데이트가 빠르고 breaking change가 잦다. 간단한 작업에는 오버엔지니어링이 될 수 있다. from langgraph.graph import StateGraph from langchain_openai import ChatOpenAI llm = ChatOpenAI(model="gpt-4o") def agent_node(state): response = llm.invoke(state["messages"]) return {"messages": state["messages"] + [response]} graph = StateGraph(dict) graph.add_node("agent", agent_node) graph.set_entry_point("agent") app = graph.compile() ## CrewAI "팀 협업" 개념을 도입한 프레임워크. 여러 에이전트가 각자 역할을 맡아 협력한다. **장점**: 직관적인 개념 — Agent(역할), Task(할 일), Crew(팀)로 구성한다. 역할 기반 설계라 비개발자도 이해하기 쉽다. 에이전트 간 위임(delegation)이 자연스럽다. 코드가 간결하고 러닝커브가 낮다. **단점**: 복잡한 분기 로직이 필요하면 유연성이 부족하다. LangChain에 비해 커뮤니티와 플러그인이 적다. 세밀한 제어가 어려울 수 있다. from crewai import Agent, Task, Crew researcher = Agent( role="리서처", goal="최신 AI 트렌드를 조사한다", backstory="10년 경력의 AI 리서처", llm="gpt-4o" ) writer = Agent( role="작가", goal="리서치 결과를 블로그 글로 작성한다", backstory="기술 블로그 전문 작가", llm="gpt-4o" ) research_task = Task(description="2026년 AI 에이전트 트렌드 조사", agent=researcher) write_task = Task(description="조사 결과를 블로그 글로 작성", agent=writer) crew = Crew(agents=[researcher, writer], tasks=[research_task, write_task]) result = crew.kickoff() ## AutoGen (Microsoft) Microsoft가 만든 멀티 에이전트 대화 프레임워크. 에이전트 간 "대화"를 통해 문제를 해결한다. **장점**: 에이전트 간 자유로운 대화 — 토론, 피드백, 수정 과정이 자연스럽다. 코드 실행 에이전트가 내장되어 있어 코딩 태스크에 강하다. Human-in-the-loop 지원이 잘 되어 있다. 사람이 중간에 개입할 수 있다. Microsoft 생태계(Azure, Office)와 연동이 편하다. **단점**: 대화 기반이라 토큰 소비가 많을 수 있다. 에이전트가 불필요하게 긴 대화를 할 때가 있다. 프로덕션 배포 사례가 아직 적다. import autogen assistant = autogen.AssistantAgent("assistant", llm_config={"model": "gpt-4o"}) user_proxy = autogen.UserProxyAgent("user", human_input_mode="NEVER", code_execution_config={"work_dir": "output"}) user_proxy.initiate_chat(assistant, message="피보나치 수열 시각화 코드를 작성해줘") ## 어떤 걸 선택할까? 빠르게 프로토타입을 만들고 싶다 → **CrewAI** — 개념이 직관적이고 코드가 짧다. 복잡한 워크플로우가 필요하다 → **LangGraph** — 그래프 기반으로 세밀한 흐름 제어 가능. 코딩/분석 태스크가 많다 → **AutoGen** — 코드 실행과 에이전트 간 대화가 강점. 프로덕션 레벨 서비스 → **LangChain** — 생태계가 넓고 모니터링 도구가 성숙. 실제로는 하나만 쓰는 게 아니라, 상황에 따라 섞어 쓰는 경우도 많다. 중요한 건 프레임워크가 아니라 에이전트 설계다. 역할, 도구, 흐름을 잘 설계하면 어떤 프레임워크든 좋은 결과를 낸다. ## 2026년 트렌드 에이전트 프레임워크는 점점 "표준화" 방향으로 가고 있다. Anthropic의 MCP가 도구 연결 표준이 되고, OpenAI의 Agents SDK가 나오면서 생태계가 정리되는 중이다. 어떤 프레임워크를 쓰든, ReAct 패턴과 Tool Use의 원리를 이해하는 게 가장 중요하다.
