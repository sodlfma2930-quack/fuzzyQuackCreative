Git 태깅(Tagging) 완전 정리 — 버전 관리의 이정표를 찍는 기술

커밋은 계속 쌓이는데, "이 시점이 v1.0이었지?"를 어떻게 찾을까? Git 태그(Tag)는 특정 커밋에 이름표를 붙이는 기능이다. 릴리즈, 배포, 마일스톤 지점을 명확하게 표시할 수 있다. ## Git 태그란? 태그는 특정 커밋을 가리키는 고정된 참조(reference)다. 브랜치는 새 커밋이 생기면 앞으로 이동하지만, 태그는 한 번 찍으면 움직이지 않는다. 브랜치: A → B → C → D (HEAD가 계속 이동) 태그: A → B → C(v1.0) → D → E(v1.1) ↑ 고정 ↑ 고정 "이 커밋이 v1.0 릴리즈다"라고 영구적으로 마킹하는 것이다. ## Lightweight Tag vs Annotated Tag Git 태그에는 두 종류가 있다. **Lightweight Tag** — 단순한 포인터. 커밋 해시에 이름만 붙인다. git tag v1.0 git tag v1.0 abc1234 메타데이터가 없다. 임시 마킹이나 로컬 작업용으로 적합하다. **Annotated Tag** — 태그 자체가 Git 객체로 저장된다. 작성자, 날짜, 메시지가 포함된다. git tag -a v1.0 -m "첫 번째 정식 릴리즈" git tag -a v1.0 -m "첫 번째 정식 릴리즈" abc1234 릴리즈용으로는 반드시 Annotated Tag를 쓴다. 누가, 언제, 왜 이 버전을 찍었는지 기록이 남기 때문이다. git show v1.0 tag v1.0 Tagger: jeong <dev@example.com> Date: Thu May 22 16:28:00 2026 +0900 첫 번째 정식 릴리즈 commit abc1234... ## 태그 기본 명령어 **태그 목록 보기** git tag git tag -l "v1.*" **태그 상세 정보** git show v1.0 **태그 삭제** git tag -d v1.0 **원격에 태그 푸시** git push origin v1.0 git push origin --tags 태그는 기본적으로 push되지 않는다. 명시적으로 push해야 원격에 반영된다. **원격 태그 삭제** git push origin --delete v1.0 ## 시맨틱 버저닝 (Semantic Versioning) 태그 이름은 보통 시맨틱 버저닝을 따른다. v{MAJOR}.{MINOR}.{PATCH} **MAJOR**: 호환성이 깨지는 변경. API가 바뀌거나 기존 기능이 삭제될 때. **MINOR**: 하위 호환되는 새 기능 추가. 기존 코드는 그대로 동작. **PATCH**: 버그 수정. 기능 변경 없음. 예시: v1.0.0 → 첫 정식 릴리즈 v1.1.0 → 새 기능 추가 (검색 기능) v1.1.1 → 검색 버그 수정 v2.0.0 → API 전면 개편 (하위 호환 안 됨) 프리릴리즈 버전도 가능하다. v2.0.0-alpha.1 v2.0.0-beta.3 v2.0.0-rc.1 ## 실전 워크플로우 **1. 개발 완료 → 태그 생성 → 배포** git checkout main git pull origin main git tag -a v1.2.0 -m "사용자 프로필 기능 추가" git push origin v1.2.0 **2. GitHub Release와 연동** GitHub에서 태그를 push하면 Releases 탭에 자동으로 나타난다. 여기서 릴리즈 노트를 작성하고 빌드 파일을 첨부할 수 있다. gh release create v1.2.0 --title "v1.2.0" --notes "사용자 프로필 기능 추가" GitHub Actions에서 태그 push를 트리거로 자동 배포하는 것도 가능하다. on: push: tags: - 'v*' 이렇게 하면 `v`로 시작하는 태그가 push될 때마다 배포 파이프라인이 실행된다. **3. 과거 커밋에 태그 붙이기** 이미 지나간 커밋에도 태그를 붙일 수 있다. git log --oneline git tag -a v0.9.0 -m "베타 릴리즈" 7a3c2f1 ## 태그 vs 브랜치 브랜치: 작업의 흐름. 계속 변한다. 개발, 기능 추가에 사용. 태그: 시점의 스냅샷. 고정된다. 릴리즈, 배포 지점에 사용. 브랜치는 "진행 중인 작업"이고, 태그는 "완료된 결과물의 이정표"다. ## 태그 관련 유용한 팁 **최신 태그 확인** git describe --tags --abbrev=0 **두 태그 사이의 변경사항** git log v1.0.0..v1.1.0 --oneline 릴리즈 노트를 자동 생성할 때 유용하다. **태그 기준 체크아웃** git checkout v1.0.0 이러면 Detached HEAD 상태가 된다. 해당 버전의 코드를 확인하거나 핫픽스 브랜치를 만들 때 쓴다. git checkout v1.0.0 git checkout -b hotfix/v1.0.1 ## 정리 태그는 Git에서 가장 간단하면서도 실무에서 빠질 수 없는 기능이다. Annotated Tag + 시맨틱 버저닝 조합을 기본으로 쓰고, GitHub Release와 CI/CD 트리거까지 연결하면 프로페셔널한 릴리즈 관리가 완성된다. 커밋 로그를 스크롤하며 "그때 그 버전 어디였더라" 하는 일은 이제 없다.
